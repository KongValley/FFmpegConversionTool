# 音视频转换工具

Windows 10/11 x64 桌面端音视频批量转换工具：Electron + Vue 3 + FFmpeg，NVIDIA 显卡时自动使用 NVENC 硬件编码，失败自动回退 CPU。

- 拖入文件或文件夹 → 选格式与质量 → 一键批量转换，实时显示进度、速度与剩余时间。
- FFmpeg 首次启动自动下载（BtbN win64-gpl 构建，含 NVENC），之后离线可用。

## 功能

- **批量队列**：一次拖入多个文件或整个文件夹（递归收集媒体文件），默认为串行转换，“并行转换”可开到 2–4 个同时进行，可单独取消或全部取消；可“暂停全部 / 继续队列”（暂停 = 中断并退回队列，恢复后从头重跑），同一文件在排队或运行中时重复添加会被跳过。
- **输入**：常见音视频格式，外加 MPEG-TS 分片与本地 HLS 播放列表（`.m3u8` / `.m3u`，分片可位于同目录或网络地址）。
- **预设格式**：MP4（H.264 / H.265 / AV1）、MKV（H.264 / H.265）、MOV（H.264）、WebM（VP9）、MP3、M4A、WAV、FLAC、OGG（Opus）、AAC、原始音轨、GIF、PNG / JPG 图片。
- **容器互转与免重编码**：勾选“复制视频流”即可只换封装（TS → MP4 秒级完成）；音频编码再选“复制”时整条都不重编码。容器或编码不兼容时按 ffmpeg 报错只回退被拒绝的那一路并提示。
- **剪辑与画面**：按起止时间裁剪、按 `W:H:X:Y` 裁剪画面、旋转 90°/180°/270°、音量归一化（loudnorm -16 LUFS，单遍）。
- **无损合并**：勾选 2 个以上“等待中”任务一键拼成一个文件（concat demuxer + 复制流，秒级完成）；要求视频编码/分辨率与音频参数一致，不一致时明确报错而不静默重编码。
- **图片帧导出**：PNG / JPG 单帧（指定时间点）或按固定间隔导出序列目录。
- **硬件加速**：NVENC 优先（H.264/H.265/AV1），启动时用黑帧实机验证驱动可用性；GPU 编码失败自动回退 CPU 并提示。高级面板可额外开启 `-hwaccel cuda` 硬件解码。
- **高级参数**：质量优先（CRF/CQ）或指定码率、分辨率（含自定义 W×H）、帧率、音频编码（含“复制”，配合复制视频流即整条无损）/码率/声道/采样率、追加任意 FFmpeg 参数。
- **失败重试**：失败任务一键重试，重新探测媒体信息并重新计算不冲突的输出路径。
- **桌面体验**：批量结束发系统通知（窗口失焦时）、任务栏显示总进度、窗口大小/位置与高级参数自动记忆。
- **健壮性**：设置文件或队列快照损坏时逐项回落默认（坏条目直接丢弃），指定输出目录不可用自动回退同源目录，退出时结束运行中的 FFmpeg 子进程。

## 系统要求

- Windows 10 / 11 x64
- 首次启动需要能访问 GitHub Releases（下载 FFmpeg，约 200 MB）；也可用环境变量指定本地副本离线安装
- GPU 加速需要 NVIDIA 显卡与较新驱动；无 NVIDIA 显卡时全部走 CPU，功能不受影响

## 快速开始

1. 从 GitHub Releases 下载 `media-converter-<版本>-win-x64.zip`（由 GitHub Actions 自动构建）。
2. 解压到独立文件夹，运行 `音视频转换工具.exe`（免安装，zip 根目录即程序文件）。
3. 首次启动会自动下载并校验 FFmpeg，看到顶栏显示 `FFmpeg <版本> · GPU：NVENC …` 即可使用。

程序数据位于 `%APPDATA%/media-converter`：`settings.json`（设置）、`queue.json`（未完成队列快照）与 `bin/ffmpeg/`（FFmpeg 缓存）。

## 使用

| 操作 | 说明 |
|---|---|
| 添加 | 拖入文件/文件夹，或点“添加文件”；提示“已添加 N 项”，被跳过时附带跳过项数与“其中 K 项已在队列”。已在排队/运行中的同一文件会跳过，已完成/失败的任务不拦（换预设可重转） |
| 格式 | 右侧“目标格式”分组为 视频 / 音频 / 动图 / 图片 |
| 质量 | 高 / 中 / 低（音频预设不显示，改用音频码率） |
| 加速 | `自动（GPU 优先）` 或 `仅 CPU`；无硬件编码器的格式会禁用并说明 |
| 上传兼容 | 高级参数里勾选后强制 H.264 High、8bit 4:2:0、去隔行、AAC 48k 立体声，云端/浏览器可直接播放；仅目标格式为 MP4 (H.264) 时可用，会忽略“复制视频流”与声道源设置，合并输出是复制流、不受影响 |
| 输出目录 | 默认同源目录；自定义目录在入队时检查，不存在/不是文件夹/不可写就本批回退同源目录并在行内标注原因（设置里的路径不改动） |
| 并行转换 | “转换设置”里的下拉：1（串行）/ 2 / 3 / 4，默认 1；每次“开始转换”时读取 |
| 开始转换 | 队列中排队任务按并行设置执行（默认 1，即依次执行）；运行中可单独取消或“取消全部” |
| 暂停 / 继续 | 工具栏“暂停全部”中断运行中的任务并退回等待队列（进度清零），“继续队列”从头重跑；暂停期间不启动新任务 |
| 磁盘空间 | 入队时按码率×时长估算输出体积，剩余空间可能不足只做行内提示，不阻断转换 |
| 合并 | 勾选 2 个以上“等待中”任务 → 点“合并所选 (N)”，原任务替换为一个 `<首个原名>_merged.<扩展名>` 任务并立即开始转换 |
| 完成后 | “打开所在文件夹”定位输出文件；列表上方可“全选 / 移除所选 / 清空队列”（只清列表，不删已转换的文件） |
| 关闭与恢复 | 关窗口会先结束运行中的 FFmpeg；未完成任务写入 queue.json，下次启动恢复到队列并保持“等待中”，不会自动开始 |

输出文件名为 `<原名>_converted.<扩展名>`，已存在时依次尝试 `_converted_2`、`_converted_3`，**不覆盖**已有文件。

## 预设格式

| 预设 | 容器 | 视频编码（GPU / CPU） | 音频编码 |
|---|---|---|---|
| MP4 (H.264) | mp4 | `h264_nvenc` / `libx264` | aac |
| MP4 (H.265) | mp4 | `hevc_nvenc` / `libx265` | aac（写入 `hvc1` 标签） |
| MP4 (AV1) | mp4 | `av1_nvenc` / `libsvtav1` | aac |
| MKV (H.265) | mkv | `hevc_nvenc` / `libx265` | aac |
| MKV (H.264) | mkv | `h264_nvenc` / `libx264` | aac |
| MOV (H.264) | mov | `h264_nvenc` / `libx264` | aac |
| WebM (VP9) | webm | 无硬件编码器，`libvpx-vp9` | libopus |
| MP3 / M4A / WAV / FLAC | mp3 / m4a / wav / flac | 仅音频（`-vn`） | libmp3lame / aac / pcm_s16le / flac |
| OGG (Opus) | ogg | 仅音频 | libopus |
| AAC (.aac) | aac | 仅音频 | aac |
| 原始音轨（不重编码） | 随源编码 | 仅音频，`-c:a copy` | 无（直接复制） |
| GIF | gif | palettegen + paletteuse（15 fps） | 无 |
| PNG / JPG 图片 | png / jpg | 单帧或间隔序列，`-an` | 无 |

原始音轨的输出扩展名按源音频编码决定：`aac→m4a`、`mp3→mp3`、`opus→opus`、`vorbis→ogg`、`flac→flac`、`alac→m4a`、PCM 系列→`wav`、`ac3/eac3` 同名，其余落入 `mka`。

质量档位对应编码参数：

| 编码器 | 高 | 中 | 低 |
|---|---|---|---|
| libx264 | slow / CRF 18 | medium / CRF 23 | faster / CRF 28 |
| libx265 | slow / CRF 20 | medium / CRF 24 | faster / CRF 28 |
| libsvtav1 | preset 4 / CRF 28 | preset 6 / CRF 32 | preset 8 / CRF 36 |
| libvpx-vp9 | CRF 24 | CRF 31 | CRF 36（`-b:v 0 -row-mt 1`） |
| h264_nvenc | p6 / CQ 19 | p5 / CQ 23 | p4 / CQ 28 |
| hevc_nvenc | p6 / CQ 21 | p5 / CQ 25 | p4 / CQ 29 |
| av1_nvenc | p6 / CQ 24 | p5 / CQ 28 | p4 / CQ 32 |

## 互转速查

| 想做什么 | 选择 |
|---|---|
| 换容器不重编码（TS/MKV/MOV → MP4 等，秒级） | 目标容器预设 + 高级面板勾选“复制视频流”；音频编码再选“复制”则音频也不重编码（整条无损） |
| 视频压缩 | MP4 (H.264/H.265/AV1) 或 MKV / MOV，质量高/中/低 |
| 视频提取音频（重编码） | MP3 / M4A / WAV / FLAC / OGG (Opus) / AAC |
| 视频提取原音轨（不重编码） | 原始音轨（不重编码），扩展名随源编码 |
| 音频之间互转 | MP3 / M4A / WAV / FLAC / OGG (Opus) / AAC 任意互转 |
| HLS/TS 转 MP4 | 拖入 `.m3u8` 或单个 `.ts`，选 MP4 (H.264)，可叠加“复制视频流”与音频“复制”（整条无损） |
| 视频剪辑（起止时间/裁剪/旋转） | 高级参数“剪辑”“画面”组；复制模式下仅时间裁剪生效 |
| 合并分片或同参数视频 | 勾选多个“等待中”任务 → “合并所选”（视频编码与分辨率、音频有无与参数必须一致） |
| 视频转 GIF | GIF（15 fps，宽度取“分辨率”） |
| 视频取帧/截图 | PNG / JPG 图片：单帧（时间点）或间隔序列目录 |

## 环境变量

| 变量 | 作用 |
|---|---|
| `FFMPEG_DIR` | 直接指定含 `ffmpeg.exe` / `ffprobe.exe` 的目录，跳过下载（目录缺文件会明确报错） |
| `FFMPEG_ZIP_PATH` | 指定本地 `ffmpeg-master-latest-win64-gpl.zip`，跳过网络下载 |

## 发布

日常使用本地打包即可，GitHub Release 由云端 Actions 生成：

| 场景 | 操作 | 结果 |
|---|---|---|
| 本地自用 | `npm run dist` | 只在 `release/` 生成 zip，不发布（`--publish never`） |
| 云端发布 | `git tag v0.6.0 && git push origin v0.6.0` | 触发 `.github/workflows/release.yml`：类型检查 + 单元测试 → 打包 → 发布 GitHub Release（附件即 zip） |
| 仅构建不发版 | Actions 页面手动 `Run workflow` | 上传构建物到该次运行的 Artifacts，不创建 Release |

- 打 tag 前请同步 `package.json` 的 `version`：CI 会校验两者一致，不一致直接失败。
- `npm run smoke`（真实 NVENC/NVDEC 转码）需要 NVIDIA 显卡，只在本地执行，CI 不跑。

## 开发

需要 Node.js ≥ 22.12。

```bash
npm install
npm run dev        # 开发模式启动（electron-vite + HMR）
npm run typecheck  # vue-tsc + tsc，零告警
npm test           # 单元测试：参数生成、进度解析、路径扫描、剪辑时长与合并校验
npm run smoke      # 真实转码冒烟：CPU/GPU 编码、硬件解码、TS→MP4 复制、HLS、音频互转、图片帧、时间裁剪、无损合并（首次约 200MB 下载）
npm run dist       # 打包免安装 zip 到 release/
```

```
src/
  shared/     纯逻辑：类型、预设表、FFmpeg 参数生成、进度解析、设置默认值（无 Electron 依赖）
  main/       Electron 主进程：FFmpeg 安装与能力探测、ffprobe、任务队列（支持并行）、IPC
  preload/    contextBridge 暴露的类型化 API（contextIsolation + sandbox）
  renderer/   Vue 3 界面：队列列表、转换设置、高级参数
test/         node:test 单元测试
scripts/      smoke.ts（真实转码验证）、make-icon.mjs（生成应用图标）
```

设计要点：

- FFmpeg 参数由 `src/shared/args.ts` 的纯函数生成，主进程与冒烟脚本共用同一份逻辑，测试直接断言参数数组。
- 主进程用 `-progress pipe:1` 解析进度，200 ms 节流广播；取消走 `taskkill /PID <pid> /T /F` 并删除半成品。
- 硬件能力在启动时实测（`-encoders` + 黑帧编码），失败即按 CPU 处理，不阻断转换。

## 已知限制

- 只保留首条视频与首条音频流，字幕与数据流不写入输出（`-sn -dn`）。
- “额外 FFmpeg 参数”按空白切分，不支持引号与转义。
- GIF 固定 15 fps，仅“分辨率”中的宽度生效。
- 复制视频流模式下不支持缩放与改帧率（`-vf`/`-r` 无法作用于复制的码流）；画面裁剪与旋转同理被忽略，只有时间裁剪生效。目标容器不支持源编码时自动重新编码并提示。
- 音频选择“复制”时不重新编码：容器或编码不兼容（如 WMA 音轨写入 MP4）时自动回退重编码并提示；此时音量归一化（需解码）不生效，“声道”“采样率”也不参与。
- 合并只做无损拼接：所选文件的视频编码/分辨率、音频有无及其编码/采样率/声道必须完全一致，不一致时直接报错；合并任务忽略剪辑与画面参数（复制流无法应用滤镜）。
- 音量归一化是单遍 `loudnorm`（I=-16 / TP=-1.5 / LRA=11），不做两遍测量，响度精度低于广播级工具。
- m3u8 仅支持本地播放列表文件；其分片可在同目录或网络地址（播放列表会自动放开 `file,http,https,tcp,tls,crypto` 协议白名单）。拖入整个 HLS 目录会把 `.ts` 分片当独立文件入队，请直接拖播放列表。
- 没有 `#EXT-X-ENDLIST` 的直播播放列表会一直转码下去（进度按已知时长显示），需要手动取消；录播播放列表（含 ENDLIST）会正常结束。
- 图片序列输出到 `<原名>_converted_frames` 目录，帧从 `0001.png` 起编号；间隔为整数秒。
- 原始音轨的输出扩展名取决于源音频编码，未知编码输出 `.mka`。
- 硬件解码开关仅对 NVDEC 支持的编码有效；遇到不支持的编码 FFmpeg 会回退软件解码，失败时请关闭该开关重新添加文件。
- 队列默认为串行（1 个任务）；“并行转换”可同时跑 2–4 个文件，并发数在每次“开始转换”时读取，批次中途改设置只影响下一批。NVENC 并发会话受驱动限制，超出的任务会自动回退 CPU。
- 暂停是「中断运行中的任务并退回等待队列」，继续后从头重跑，不冻结 ffmpeg 进程。
- 队列恢复不自动开始转换，也不恢复暂停状态；同时开两个实例会各自读写 `queue.json`、后写者覆盖前者（未做单实例保护）。
- 磁盘空间提示基于码率×时长的估算，质量模式（CRF）只能给上界，可能误报；提示不会阻止转换。
- 输出目录回退只作用于当前这一批任务，不改写设置里的路径；目录恢复可用后自动继续使用。
- 文件夹递归扫描遇到无权限或扫描中被删除的子目录时只跳过，并计入“跳过 N 项”，不单独列出目录名。

## 后续计划

按「价值 / 成本」排序，以下均未实现：

| 优先级 | 功能 | 现状与做法 |
|---|---|---|
| P1 | 音轨与字幕选择 | 现在固定 `-map 0:v:0 -map 0:a:0` 并丢弃字幕（`-sn -dn`）；计划在高级参数里列出探测到的音轨/字幕供勾选 |
| P1 | 输出文件名模板 | 现在硬编码 `<原名>_converted.<扩展名>`、`_converted_frames`、`_merged`；计划支持 `${name}_${preset}.${ext}` 这类模板 |
| P2 | 每任务独立目标格式 | 预设按入队时的全局设置写入每个任务（`job.options.presetId`），入队后无法单独指定/修改（同一批添加只能一个格式）；计划支持对勾选任务单独指定 |
| P2 | 队列筛选与批量改预设 | 队列操作只有全选 / 移除所选 / 清空队列（有失败任务时另有“重试全部失败”）；计划增加按状态过滤，以及“对所选改预设后重新排队” |
| P3 | 真暂停（冻结进程） | 现在的暂停是中断后从头重跑；原地续跑需要经 ntdll 挂起 ffmpeg，成本与失败面更大 |
| P3 | 单实例保护 | 未调用 `requestSingleInstanceLock()`，两个实例会互相覆盖 `queue.json` |
